## Publication and accepted turns

The production publisher returns `publishedAttachmentIds` and `cacheFailures`. Only `quota_exceeded` and ordinary `cache_write_failed` are safe cache outcomes. It checks current ownership/private access and source bytes around publication, and checks all prepared sources again before finishing a multi-document attempt. Ready-manifest publication remains atomic; a write that mutates and then throws restores the previous ready record or fails closed. Existing indexes and owners are not evicted to make room.

After `appendMessage`, the user callback runs once and history owns persisted attachments/images. A safe cache failure continues the answer using the already selected and checked Hybrid/reranked fragments, after the confirmed restoration of A. It starts no repeated embedding/rerank operation. The actual mode remains `hybrid` / `hybrid+rerank`; a separate localized warning says the index was not saved and later search may need preparation again. A failed index is not Ready and cannot be recovered as a partial index after restart.

Cancellation, chat/model/rights changes, source changes/deletion, blocked/reset private storage, unknown drain and failed A restoration remain fatal to the old request. Post-append guards cover changed inference settings and source bytes before creating the assistant placeholder. Temporary vectors are released; generation ownership is finished even when cleanup fails. Branch replacement preserves an already committed answer when the derived-cache publication fails and still performs retention/resource cleanup. Empty branch rollback and tool-history recovery keep their existing contracts.

Cold persistence also preserves materialized document-image linkage in its canonical generic form. The same-message parent/path validation still rejects missing, malformed and foreign assets.
