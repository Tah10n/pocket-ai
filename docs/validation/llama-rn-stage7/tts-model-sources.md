# Voice execution source record

The exact artifact identities are in [tts-fixtures.json](tts-fixtures.json). This record describes source contracts and bounded execution profiles. It does not establish native inference, intelligibility, speaker similarity, peak memory or device acceptance. Existing Stage 6 OuteTTS and BlueMagpie profiles and decoder bounds remain unchanged.

## Builtin voice and offline phonemes

[NeuTTS Nano GGUF](https://huggingface.co/BricksDisplay/NeuTTS-Nano-GGUF/tree/857e272b903daf826606567c9ceaef574bfa793b) plus its NeuCodec Q8 artifact is the selected English builtin profile. Unique artifacts total 551,290,944 bytes; the two codec-loading paths in rc.3 bring the artifact baseline to 893,010,112 bytes before graphs and dequantization. The GGUF decoder hop is 480 samples at 24 kHz, hence 800 frames for the existing 16-second clip limit.

The [rc.3 voice registry](https://github.com/mybigday/llama.rn/blob/v0.13.0-rc.3/src/tts-voices.ts) provides `default`, `dave`, `jo` under `en-us`; `default` aliases Jo. It also provides German and French entries, but those do not admit German/French speech from this English Nano backbone. Speech admission `en`, builtin lookup `en-us` and phonemizer `en-us` are separate fields. The runtime intersects all three public voice/language helpers with the profile and verifies native capabilities before formatting.

Jo contains 653 immutable reference codes and Dave 372. The new Neu profile allows 1,536 full prompt tokens including reference conditioning; Stage 6 profiles retain 512. Main input remains bounded to 240 characters, output to 16 seconds, and the complete native prompt must fit the configured context. No reference prompt or text is silently cut.

The [upstream NeuTTS license](https://github.com/neuphonic/neutts/blob/main/LICENSE) is the NeuTTS Open License v1.0, with revenue-dependent commercial-use terms covering models, derivatives and outputs. The [NeuCodec card](https://huggingface.co/neuphonic/neucodec) declares Apache-2.0. Model artifacts are not redistributed in this change.

[phonemize 2.0.1](https://www.npmjs.com/package/phonemize/v/2.0.1) is a local rule/dictionary G2P implementation, also used by the [tagged llama.rn example](https://github.com/mybigday/llama.rn/blob/v0.13.0-rc.3/example/src/screens/TTSScreen.tsx). The English package entry resolves to `dist/index.cjs`, importing only core, English G2P, English JSON dictionaries and the shared AnyASCII table. It imports neither Chinese/Pinyin nor the other language processors. No Node, WASM, browser worker, file read, network request or installation hook is required by this runtime entry. JSON dictionaries are separate files in the published package. Metro/Hermes compilation and pronunciation quality still require native validation.

The output is Unicode IPA with stress and punctuation retained, word spaces and separate `dʒ`/`tʃ` affricates. The app disables transliteration, rejects unsupported scripts/language keys, bounds output to 4,096 characters, checks ownership before/after conversion, and rejects output taking over one second only after the real synchronous call settles. English US output is not claimed byte-identical to [Neuphonic's eSpeak backend](https://github.com/neuphonic/neutts/blob/main/neutts/phonemizers.py). The app keeps existing builtin `ref_phones` unchanged and phonemizes a payload's `ref_text` separately when required.

Package code is MIT. The [dictionary build script](https://github.com/hans00/phonemize/blob/main/scripts/build-dict.ts) uses English US IPA data from [ipa-dict](https://github.com/open-dict-data/ipa-dict), whose English credits point to [cmudict-ipa](https://github.com/lingz/cmudict-ipa); these use MIT notices, with the original CMU dictionary notice retained. [Kyubyong/g2p](https://github.com/Kyubyong/g2p) and [Misaki](https://github.com/hexgrad/misaki) homograph data use Apache-2.0. [AnyASCII](https://github.com/anyascii/anyascii/blob/master/LICENSE) uses ISC. Full notices are bundled in `src/thirdParty/phonemize-notices.json` and readable from the builtin voice controls. English UK GPL data is not selected by this source pipeline. The lockfile preserves exact tarball integrity and the two MIT transitive dependencies; they are not imported by the English entry.

## User reference conditioning

[Qwen3-TTS 0.6B GGUF](https://huggingface.co/BricksDisplay/Qwen3-TTS-12Hz-0.6B-GGUF/tree/f585ae3ca470e59ef9405d6317a6f11bc6c7ca1f) is the selected reference profile. Its backbone and bundled tokenizer/codec total 1,674,891,584 bytes; loading codec weights through both paths gives a 2,953,083,104-byte artifact baseline. The [base model card](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-0.6B-Base) declares Apache-2.0. Its larger language list does not expand this profile's English admission. In rc.3 the JS language argument is a registry/phonemizer hint; it is not a native synthesis-language selector.

The bundled codec advertises PCM encoder, decoder and ECAPA speaker encoder. The [actual native implementation](https://github.com/mybigday/llama.rn/blob/v0.13.0-rc.3/cpp/codec/src/lm/speaker_qwen3_tts.cpp) consumes 24 kHz mono PCM and returns one 1,024-dimensional speaker row. A stale comment elsewhere calls this encoder a stub; the implementation and call path are present. Reference policy is 0.2–8 seconds, 4,800–192,000 samples, with explicit voice permission before preparation. Original source limits are separate: 2 MiB per sample, four encrypted saved voices, 8 MiB aggregate.

Each synthesis owns a fresh context speaker: `createSpeaker(bake:false)` → explicit `bake()` or native formatter `autoBakeSpeaker` → native formatter with the actual `LlamaSpeaker` → completion → decode → speaker release → vocoder release → context release. A guarded JSI extension returns the actual registry `speakerId`, `speakerRows`, `speakerBaked` after formatting and rejects failed encoding. Missing, stale or incompatible receipts block completion. A rejected speaker release skips explicit vocoder release and retains ownership for confirmed context destruction; the guarded TTS destructor clears registry speakers and pending selection before codec teardown. This fallback reports a cleanup failure rather than successful explicit release. No handle, rows, embeddings, PCM or derivative path is persisted. `refText` is stored but never read by this Qwen native conditioning path; emotion is unused. The UI exposes neither field for this profile.

The [Qwen formatter](https://github.com/mybigday/llama.rn/blob/v0.13.0-rc.3/cpp/rn-tts.cpp) returns empty text prompt, `embedding:true`, and `talker_embd` despite the public TS union omitting that flow. Native owns the talker prefix and text projection. The runtime validates that exact form, bounds the original text token count and reserves fixed prefix rows, then uses completion's frame-major `audio_tokens` with 16 codebooks. At 24 kHz and hop 1,920, 200 frames equal 16 seconds; 201 prediction steps permit the terminating EOS. Missing EOS or excess frames are rejected before decode. Accepted native checks bound both the caller tokens and the decoder's actual accumulator before graph allocation.

OuteTTS 1.0 plus DAC is retained for speakerless speech, not offered for user reference voices: rc.3's formatter does not consume the registry handle in its Oute prompt builder. NeuTTS handles also bypass the JSON `ref_codes/ref_phones` payload required by its prompt. Chatterbox requires separate speech-tokenizer/reference-token wiring absent from the public vocoder API. These are explicit compatibility exclusions, not claims about model quality.

Peak memory is a conservative low-confidence policy estimate including duplicate weights, possible F32 materialization, graphs, KV/hidden state, bounded PCM/JSON/WAV/player copies and reference baking. The policy budgets Neu at 3,967,177,088 bytes (3.69 GiB) and Qwen at 8,837,808,576 bytes (8.23 GiB). Qwen includes 1,536 MiB graph reserve plus 64 MiB speaker/encoder reserve and 64 bytes per bounded reference sample for retained JS/bridge/native copies. Preparation while the chat context is loaded has separate admission before decoding. Devices failing that budget remain blocked. Artifact sizes or successful JS tests are not measured peak RAM or native speaker-cloning proof.
